## 2. Architecture decisions (made)
- **Static React app (Vite, JavaScript, not TypeScript), no backend, no database, no logins, no API keys, no .env.**
- Settings (language/voice) saved in `localStorage`.
- AI models run in the browser through **Transformers.js** (`@huggingface/transformers`, v4) with WebGPU, inside a **Web Worker** so the page doesn't freeze. Models download from Hugging Face on first use and are cached by the browser. Load each model **lazily** (only when its feature is first used).
- Flow: Mic button, then speech recognition, then **command router**, then one of: `open_site` (allowlist of sites), `describe_scene` (vision model), `read_text` (OCR, not the vision model), `chat` (language model). Reply is shown on screen and spoken.

| Feature | Chosen tech | Notes |
|---|---|---|
| Vision | `HuggingFaceTB/SmolVLM-256M-Instruct` (Transformers.js, WebGPU) | Apache 2.0 (verified). Optional upgrade: `SmolVLM-500M-Instruct`. |
| OCR | Tesseract.js (`tesseract.js` v7) | Apache 2.0 (confirm). English good; Hindi weaker, extra data. Use OCR (not vision) for reading text; small VLMs misread words. |
| Chat | `onnx-community/Qwen3-0.6B-ONNX` via Transformers.js | Apache 2.0 (confirm). Must disable Qwen3 "thinking mode". Fallbacks: `HuggingFaceTB/SmolLM2-360M-Instruct`, or WebLLM + Llama 3.2 1B (~700 MB). Real size not yet measured. |
| Speech to text | Browser Web Speech API (Chrome/Edge) | Free, no download, but Chrome sends audio to Google (needs internet). Optional later: Whisper-tiny via Transformers.js. |
| Text to speech | Browser `speechSynthesis` | Free; Hindi voices may be missing on some devices. Optional later: Kokoro-82M (Apache 2.0, ~86-326 MB). |
| Smart commands | Keyword/regex rules first; optional tiny embedding model (e.g. `Supabase/gte-small`) later | Don't use the 0.6B chat model as the classifier. |
| Hosting | Vercel (Hobby, free) deploying from GitHub; backup: GitHub Pages or Netlify | Models are fetched from Hugging Face, not our hosting. |

### Known limitations to keep in mind
- First model download is slow (vision model took ~55 s on first load), so the UI needs progress bars and a "Preparing the AI" screen.
- Supported target: **desktop Chrome or Edge**. Many phones can't run these models; show a clear message and keep speech/"open website" working.
- Browsers may block `window.open` triggered by a voice command (no click). Fallback: show a big "Open YouTube" button and say "Press the button".
- Small vision model is wrong ~1 time in 3 on small objects; add "Describe again", a "may be wrong" note, and prepare tested demo objects.
- "Offline" only partly true (speech recognition needs internet).

## 3. What has been done so far
### Vision feasibility test (done)
- File **`vision-test.html`** (single page, loads Transformers.js from `https://cdn.jsdelivr.net/npm/@huggingface/transformers@4`). Uses `AutoProcessor`, `AutoModelForVision2Seq`, `load_image`, `TextStreamer`, `do_image_splitting: false`, images shrunk to 640 px. WebGPU dtype: `{ embed_tokens: "fp16", vision_encoder: "q4", decoder_model_merged: "q4" }`; WASM fallback uses `q8` for all three. (API names were not verified against the package in a sandbox, but they worked on the user's laptop.)
- Result on the user's laptop (Ryzen 7 260, 24 GB RAM, RTX 5050 + AMD RDNA 3 graphics, Windows; the browser used the AMD graphics): WebGPU available; model **first load 54.9 s, cached load ~2.8 s**; runs took **4.1 s, 2.5 s, 1.8 s**. Answers: mouse photo correct (even blurred); earbuds case correct once, missed once, and once called it "a case and a remote"; text reading gave "cromolyn sodium" and "ophthalmic solution" (correctness not confirmed). Verdict: **speed passes; accuracy is the weak point.**
- Not yet tested: 500M vision model, the chat model, memory use with several models loaded, other teammates' laptops.
